# Análisis de Requerimientos — FakeStore Frontend
## Sistema de Simulación de Tienda Online
**Ingeniería de Software | Especificación de Tareas bajo Norma IEEE 830**

---

> **Nota del Proyecto:** Este documento establece la estructura funcional, las restricciones técnicas y la división de tareas específicas para el desarrollo de la primera versión de la tienda online, utilizando la API pública de *Fake Store* y almacenamiento local en el navegador para la persistencia del carrito.

---

## 1. Requerimientos Funcionales (RF)
*¿Qué debe hacer el sistema?*

### Acceso y Usuarios (Autenticación)
* **RF1:** El sistema debe permitir iniciar sesión enviando las credenciales mediante el método `POST` al endpoint de autenticación de la API.
* **RF2:** El sistema debe validar el acceso de forma estricta con los datos de prueba provistos (`johnd` / `m38rmF%bodylt`).
* **RF3:** El sistema debe almacenar el token o la sesión de manera local en el navegador (`localStorage` o `sessionStorage`) al recibir una respuesta exitosa.
* **RF4:** El sistema debe proveer una opción visible para "Cerrar Sesión", la cual debe destruir los datos de la sesión guardados y reestructurar la vista al estado inicial.

### Perfil de Usuario
* **RF5:** El sistema debe solicitar la información del usuario logueado mediante una petición `GET` al endpoint de usuarios de la API (`/users/1`).
* **RF6:** El sistema debe renderizar dinámicamente en la sección de perfil los datos del usuario: **Nombre**, **Nombre de Usuario**, **Correo electrónico** y **Teléfono**.

### Catálogo y Navegación
* **RF7:** El sistema debe realizar una petición `GET` para obtener y mostrar de forma dinámica la lista completa de productos disponibles (`/products`).
* **RF8:** El sistema debe consultar las categorías existentes desde la API (`/products/categories`) para armar las opciones de filtrado de forma dinámica.
* **RF9:** El sistema debe permitir filtrar el catálogo por categoría mediante una petición `GET` al endpoint de productos por categoría (`/products/category/:categoria`).
* **RF10:** El sistema debe disponer de un buscador que filtre los productos por su nombre (título) en tiempo real en el cliente.

### Carrito de Compras
* **RF11:** El sistema debe permitir agregar productos al carrito guardando un objeto estructurado con: `id`, `título`, `precio`, `imagen` y `cantidad`.
* **RF12:** El sistema debe listar los ítems del carrito calculando de forma automática el subtotal por producto (`precio * cantidad`) y el **Total General**.
* **RF13:** El sistema debe permitir incrementar o decrementar la cantidad de un producto directamente desde la vista del carrito.
* **RF14:** El sistema debe permitir eliminar por completo un producto del carrito.
* **RF15:** El sistema debe persistir el estado actual del carrito en `localStorage` para evitar la pérdida de datos al recargar la página.

## 2. Requerimientos No Funcionales (RNF)
*¿Cómo debe ser el sistema?*

* **RNF1 [Arquitectura]:** La aplicación no debe poseer backend propio; será un desarrollo estrictamente Frontend estructurado en tres archivos independientes: `index.html`, `style.css` y `script.js`.
* **RNF2 [Estructura Semántica]:** El archivo HTML debe construirse utilizando etiquetas semánticas de forma estricta (`<header>`, `<nav>`, `<main>`, `<section>`, `<article>`, `<aside>`, `<footer>`) según corresponda.
* **RNF3 [Consistencia Visual]:** El diseño debe aplicar de forma coherente y en todos sus componentes (botones, tarjetas, formularios, tipografías) el estilo visual seleccionado por el grupo (ej. *Minimalista, Neobrutalism, Dark Mode, etc.*).
* **RNF4 [Robustez e Interfaz]:** El sistema debe interceptar posibles errores de conexión con la API y desplegar mensajes informativos amigables cuando no haya stock, el carrito esté vacío o la búsqueda no arroje resultados.

## 3. División de Tareas Específicas para Programación (WBS)

### Fase I: Maquetado y HTML Semántico (`index.html`)
- [ ] **Tarea 1.1:** Crear la estructura base del documento, enlazar los archivos CSS/JS y definir el contenedor global con `<header>`, `<nav>` y `<footer>`.
- [ ] **Tarea 1.2:** Construir la sección de Login (`<section id="login-container">`) utilizando la etiqueta `<form>` junto con sus respectivos inputs y botones.
- [ ] **Tarea 1.3:** Construir la sección de Perfil de Usuario (`<section id="profile">`) con marcadores de posición (placeholders) para los datos dinámicos.
- [ ] **Tarea 1.4:** Diseñar la estructura del Catálogo utilizando `<main>`, agregando un `<aside>` para los filtros/buscador y un contenedor para la grilla de productos.
- [ ] **Tarea 1.5:** Maquetar la interfaz del Carrito de Compras (`<section id="cart">`) con la estructura necesaria para listar ítems, cantidades y totales.

### Fase II: Estilos, Diseño y Maquetación CSS (`style.css`)
- [ ] **Tarea 2.1:** Configurar las variables globales (`:root`) definiendo la paleta de colores y tipografías acordes al estilo visual seleccionado.
- [ ] **Tarea 2.2:** Implementar el sistema de diseño responsivo (CSS Grid o Flexbox) para la grilla de productos y la distribución de los componentes.
- [ ] **Tarea 2.3:** Diseñar los componentes individuales: tarjetas de producto (`<article>`), botones de acción, campos de formulario y estados (`:hover`).
- [ ] **Tarea 2.4:** Crear clases utilitarias de control de flujo (ej. `.hidden { display: none; }`) para manejar la visibilidad de las secciones desde JavaScript.

### Fase III: Lógica, Consumo de API y Manipulación del DOM (`script.js`)
- [ ] **Tarea 3.1: Módulo de Autenticación (Login)**
  - Capturar el evento `submit` del formulario de inicio de sesión.
  - Implementar `fetch` (POST) hacia el endpoint de auth de la API.
  - Almacenar el token en el almacenamiento del navegador y alternar vistas.
- [ ] **Tarea 3.2: Módulo de Perfil y Control de Sesión**
  - Crear función de inicialización para verificar sesión activa al cargar la página.
  - Implementar `fetch` (GET) para obtener los datos de usuario e inyectarlos en el HTML.
  - Programar el evento del botón "Cerrar Sesión" (limpiar storage y reiniciar vista).
- [ ] **Tarea 3.3: Módulo de Catálogo y Renderizado Dinámico**
  - Implementar `fetch` (GET) para cargar las categorías e insertarlas en el DOM.
  - Implementar `fetch` (GET) para descargar los productos iniciales.
  - Programar la función constructora de tarjetas inyectando imagen, título, precio, categoría y el botón con el ID correspondiente del producto.
- [ ] **Tarea 3.4: Módulo de Búsqueda y Filtros**
  - Programar el evento `change` del filtro de categorías para realizar la petición dirigida a la API o filtrar la colección en memoria.
  - Programar el evento `input` en el buscador por nombre para actualizar las tarjetas visibles mediante coincidencia de texto (`String.includes`).
- [ ] **Tarea 3.5: Módulo de Carrito de Compras**
  - Inicializar el array global del carrito leyendo datos desde `localStorage`.
  - Programar la lógica "Agregar": buscar si el ID ya existe para incrementar la propiedad de cantidad o añadir el objeto nuevo al array.
  - Desarrollar la función de renderizado del carrito (actualizar el DOM, recalcular subtotales y actualizar el nodo del Monto Total).
  - Asignar listeners para los controles de cantidad (`+` / `-`) y eliminación.
  - Asegurar la persistencia llamando a `localStorage` en cada mutación del array.
